# p5play v3 Modernization Plan for Nova Zombie Simulator

**Date:** July 9, 2025  
**Status:** Draft  
**Priority:** High  

## Overview

After reviewing the p5play v3 documentation against our current Nova Zombie Simulator codebase, several modernization opportunities have been identified. Our project uses p5play v3.22.11, which includes significant API improvements and clearer collision detection patterns that could enhance our game architecture.

## Proposed Improvements

### 1. Modernize Collision Detection System

**Current Issue:** Likely using older collision patterns or inconsistent collision handling.

**Improvement:** Implement p5play v3's clearer collision API:

```javascript
// Physics-based collisions (entities bounce/push)
if (player.collides(zombie)) {
    // Handle zombie bite on first contact frame
    player.health -= 10;
}

// Non-physics overlaps (detection only)
if (bullet.overlaps(zombie)) {
    // Handle bullet hit
    zombie.remove();
    bullet.remove();
}

// Continuous collision checking
if (player.colliding(wall)) {
    // Handle wall contact every frame
}
```

**Benefits:**
- Clearer intent: `collides()` vs `overlaps()`
- Better performance: separate physics vs detection
- More predictable behavior

### 2. Implement Group-Based Entity Management

**Current Issue:** Individual entity management may lead to complex collision detection.

**Improvement:** Use p5play Groups for entity categories:

```javascript
// In nova-zombie-simulator.js
let zombies = new Group();
let humans = new Group();
let soldiers = new Group();
let bullets = new Group();
let doctors = new Group();

// Group-based collision detection
zombies.overlaps(humans, (zombie, human) => {
    // Convert human to zombie
    human.remove();
    createZombie(human.x, human.y);
});

soldiers.overlaps(zombies, (soldier, zombie) => {
    // Soldier kills zombie
    zombie.remove();
});

bullets.overlaps(zombies, (bullet, zombie) => {
    bullet.remove();
    zombie.remove();
});
```

**Benefits:**
- Simplified collision management
- Better performance with many entities
- Cleaner code organization
- Easier to add new entity types

### 3. Modernize Sprite Creation Patterns

**Current Issue:** May be using older sprite constructor patterns.

**Improvement:** Use p5play v3's flexible constructor:

```javascript
// In entity modules (e.g., nova.zombie.js)
export function createZombie(x, y, image = null) {
    let zombie;
    
    if (image) {
        zombie = new zombies.Sprite(image, x, y, 32, 32);
    } else {
        zombie = new zombies.Sprite(x, y, 32, 32);
        zombie.color = 'green';
    }
    
    // Modern property names
    zombie.speed = 2;
    zombie.bounciness = 0.3; // was 'restitution'
    zombie.drag = 0.1; // was 'linearDamping'
    
    return zombie;
}
```

### 4. Implement Animation System

**Current Issue:** Static sprites without animations.

**Improvement:** Add sprite animations using p5play v3's animation API:

```javascript
// In entity creation functions
zombie.addAni('walking', 'zombie-spritesheet.png', {
    pos: [0, 0],
    frames: 4,
    delay: 200,
    rotation: 0
});

zombie.addAni('attacking', 'zombie-spritesheet.png', {
    pos: [0, 1],
    frames: 3,
    delay: 150
});

// Change animations based on state
if (zombie.speed > 0) {
    zombie.changeAni('walking');
} else {
    zombie.changeAni('idle');
}
```

### 5. Enhanced Physics Properties

**Current Issue:** May not be using p5play v3's improved physics property names.

**Improvement:** Use beginner-friendly property names:

```javascript
// Soldier entities
soldier.isSuperFast = true; // prevents bullet tunneling
soldier.bounciness = 0.1; // low bounce for realistic movement
soldier.drag = 0.2; // realistic movement resistance

// Bullet entities
bullet.isSuperFast = true; // essential for fast-moving bullets
bullet.drag = 0; // no air resistance for bullets
```

## Implementation Plan

### Phase 1: Group System Migration
1. **Update main game file** (`nova-zombie-simulator.js`)
   - Create Group instances for each entity type
   - Migrate existing collision detection to group-based system

2. **Update entity modules**
   - Modify creation functions to use group constructors
   - Export factory functions instead of classes if needed

### Phase 2: Collision System Modernization
1. **Audit current collision code**
   - Identify physics vs detection use cases
   - Replace with appropriate `collides()` or `overlaps()` calls

2. **Implement group collision callbacks**
   - Zombie-human interactions
   - Bullet-entity interactions
   - Player-pickup interactions

### Phase 3: Animation Integration
1. **Create sprite sheets** for entities
2. **Implement animation states** per entity type
3. **Add state-based animation switching**

### Phase 4: Physics Optimization
1. **Update property names** to p5play v3 standards
2. **Fine-tune physics values** for game feel
3. **Performance testing** and optimization

## Technical Considerations

### Breaking Changes to Watch
- `sprite.touching` → `sprite.colliding()` / `sprite.overlapping()`
- `sprite.mirrorX` → `sprite.mirror.x`
- `sprite.restitution` → `sprite.bounciness`
- `sprite.angle` → `sprite.rotation`

### Performance Benefits
- Group-based collision detection is more efficient
- Clearer separation of physics vs detection reduces unnecessary calculations
- Modern property names improve code readability and maintenance

### Testing Strategy
1. **Unit tests** for entity creation functions
2. **Integration tests** for collision detection
3. **Performance benchmarks** before/after changes
4. **Visual consistency validation** during refactoring

**Mitigation:** Performance benchmarking before/after each phase

**Mitigation:** Start with simple 2-frame animations, expand gradually
