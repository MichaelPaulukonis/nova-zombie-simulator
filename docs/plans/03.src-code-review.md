## Findings

### 1. God file: `nova-zombie-simulator.js`
One file owns: game state (`params`), mode enum, level/round logic, ALL collision detection (human/zombie/soldier/doctor pairwise checks), draw dispatch, help screen, title screen, sound loading. No separation between engine/state/rendering/UI.

**Fix path:** split into `gameState.js` (params + resetLevel/startGame), `collisions.js` (playloop pairwise checks), `screens.js` (help/pause/gameover/title render), `sound.js` (load + play wrappers). Entry file stays wiring only.

### 2. Bug: Human double-movement
`nova.human.js:10-16` — `move()` calls `super.move()` (already applies noise wander), then repeats the *same* noise-offset math again inline. Humans get 2x wander speed vs other mobiles, and burn noise offset twice per frame. Looks like copy-paste from before `super.move()` existed.

**Fix:** delete lines 13-16, keep just `super.move()`.

### 3. Copy-pasted movement logic
Screen-wrap code (`if x<0... if x>width...`) duplicated identically in `Mobile.move()`, `Human.move()`, `Player.move()`. Belongs only in `Mobile`, reached via `super.move()`.

Steer-toward/away angle math (`atan2` + `cos/sin`) near-identical across Zombie/Soldier/Doctor, only sign and speed differ.

**Fix:** pull into `Mobile.steerToward(target, speed)` / `steerAway(target, speed)`.

### 4. Bug/leak: killed zombies never removed
`Zombie.kill()` only flags `killed=true` and swaps to tombstone emoji. Zombie stays in `params.zombies` forever — still `move()`d and `display()`d each frame (early-return guarded, but never spliced). Every other transformation (human→zombie, zombie→human) correctly splices/pushes; kill is the one inconsistent path. Array grows unbounded across a play session.

**Fix:** splice killed zombies out of `params.zombies`, same pattern as the other transitions.

### 5. Redundant re-randomization
`Soldier`/`Doctor` constructors call `super(ctx,x,y,...)` (already randomizes x/y when null), then immediately re-randomize x/y again right after (`nova.soldier.js:8-9`, `nova.doctor.js:7-8`). Dead code — author flagged it themselves (`// mmmmm hrm`).

**Fix:** delete the redundant lines.

### 6. `resetLevel()` builds `gameObjs` twice
`nova-zombie-simulator.js:80` then again `:101` — first assignment is dead, overwritten before use.

### 7. Magic numbers, no config
Proximity thresholds (50/100/200), steer speeds (2/3/5), timers (2000ms invuln, 3000ms doctor wait), sprite size (20) — inline literals scattered per-class. Hurts tunability: changing "doctor heal cooldown" means hunting through `nova.doctor.js`.

**Fix:** centralize into a `config.js` (or extend `params`) with named constants.

### 8. HELP screen instantiates real entities
`displayHelp()` does `new Human`, `new Soldier`, `new Zombie`, `new Doctor`, `new Player` — each spins up a real p5play `Sprite` (physics body) just to draw a static legend icon. Wasteful, couples help screen to full entity construction cost/side-effects.

**Fix:** draw emoji glyphs directly with `p.text()` instead.

### 9. Library underuse: p5play/planck barely touched
p5play (`Sprite`) and planck (physics engine, `window.planck`) are imported, but every entity does hand-rolled Perlin-noise movement and manual `dist()` checks — no p5play collision groups, `.overlaps()`, or planck physics bodies actually used. Paying import/init cost of a physics engine for none of its ergonomic payoff.

**Fix:** either lean into p5play (sprite groups + `.overlap()` would replace the nested `for` loops in `playloop()`), or drop planck/physics sprites for lighter primitives.

### 10. Scaling concern
`playloop()` is O(humans × zombies × soldiers × doctors) nested loops every frame, and `resetLevel()` raises `humanLimit`/`soldierLimit` every even level — cost grows unbounded as rounds progress. Fine at current entity counts; revisit with p5play sprite groups if entity types/caps grow further.

### 11. Dead file: `single_sketch.js`
Not referenced by `index.html` or any import — confirmed orphaned scaffold. Delete.
